# Non-SYSTEM Privileged Logon Detection

## Detection Name

SOC Lab - Non-SYSTEM Privileged Logon

## Objective

Detect Windows Security Event ID 4672 when special privileges are assigned to a new logon on the monitored endpoint while excluding the known routine NT AUTHORITY\SYSTEM context.

## Data Source

Microsoft Sentinel SecurityEvent table.

## Windows Event ID

4672 - Special privileges assigned to a new logon

## Detection Query

SecurityEvent
| where EventID == 4672
| where Computer =~ "LAPTOP-JM2CHLK8"
| where Account !~ "NT AUTHORITY\\SYSTEM"
| project TimeGenerated, Computer, EventID, Activity, Account, SubjectAccount, SubjectLogonId

## Detection Tuning

Initial analysis showed that Event ID 4672 can be generated by normal privileged Windows activity.

The NT AUTHORITY\SYSTEM context was identified as expected routine activity in the lab and excluded from this alerting rule.

The underlying telemetry remains available in Microsoft Sentinel for investigation. The exclusion only reduces noise in this specific detection.

## Rule Configuration

- Rule type: Scheduled analytics rule
- Severity: Medium
- Status: Enabled
- Query frequency: 1 hour
- Lookback period: 1 hour
- Alert threshold: More than 0 results
- Event grouping: Group all events into a single alert
- Suppression: Disabled
- Incident creation: Enabled
- Alert grouping: Disabled
- Automated response: Not configured
- MITRE ATT&CK mapping: Not forced because Event ID 4672 alone does not establish a specific adversary technique

## Detection Engineering Lesson

Collection and alerting are different layers.

Security telemetry can remain available for investigation while analytics rules apply exclusions to reduce repetitive known activity.

A production exclusion should be evidence-based, narrowly scoped, documented, reviewed, and periodically reassessed.

Event ID 4672 alone does not prove privilege escalation or malicious behavior. Additional authentication, process, account, host, and timeline context is required.
